# 4626 Deep Risk Audit Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Produce a risk-ordered, evidence-backed audit of project 4626 covering auth/session, API endpoints, wallet/identity flows, docs drift, launch readiness, frontend UX safety, backtest correctness, race conditions, tests, and deployment smoke checks.

**Architecture:** This is an audit-only plan, not a refactor plan. Work from the highest-risk trust boundaries outward: authentication/session and mutating API surfaces first, wallet/identity execution next, then concurrency/race windows, docs drift, correctness, UX safety, coverage, and launch smoke gates. Every finding must cite exact file paths and a pass/fail criterion; fixes, if any, should be deferred until after the audit report is reviewed.

**Tech Stack:** 4626 monorepo; Vite 7 + React 19 + TypeScript frontend in `frontend/`; Vercel API handlers in `frontend/api/_handlers/`; server helpers in `frontend/server/_lib/`; Supabase/Postgres schema and migrations; Foundry Solidity contracts; pnpm, Vitest, ESLint, Playwright/axe, Forge, Vercel-style smoke scripts.

---

## Audit rules and deliverables

### Deliverables

1. `docs/audits/deep-risk-audit-2026-06.md` — main audit report with risk-ordered findings.
2. `docs/audits/deep-risk-audit-2026-06-endpoint-matrix.md` — endpoint inventory matrix.
3. `docs/audits/deep-risk-audit-2026-06-validation-log.md` — exact commands run, exit codes, and summarized output.
4. Optional `docs/audits/deep-risk-audit-2026-06-followups.md` — only if the audit identifies fixes too large to apply immediately.

### Severity scale

- **P0 BLOCKER:** live exploit path, unauthenticated mutation, broken launch path, compile/build failure, or a trust-boundary invariant currently violated.
- **P1 HIGH:** authenticated but misauthorized mutation, wallet/identity mismatch that can route funds through the wrong sender, stuck auth/onboarding/deploy flow, or correctness issue that materially misleads users.
- **P2 MEDIUM:** missing rate limit/timeout/body bound on expensive endpoint, race window with plausible user impact, docs drift likely to cause bad future changes, missing test for load-bearing invariant.
- **P3 LOW:** confusing UX safety copy, weak fallback/error state, stale docs with low implementation risk, low-impact coverage gaps.

### Evidence standard

A finding passes audit quality only if it includes:

- Exact file path and function/component/route.
- Trigger or precondition.
- Expected invariant.
- Observed implementation behavior.
- Severity and rationale.
- Pass/fail criterion.
- Minimal remediation recommendation, without applying it during the audit unless explicitly approved.
