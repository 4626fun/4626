## 1. C-2 — No cumulative mint cap; escrow claim not bounded by recovered

### `mintImpairmentClaim` / `mintFromVault` vs `epoch.totalClaimSupply`

**Confirmed.** `mintImpairmentClaim` validates Merkle proof, one mint per account, and non-zero `amount`, but never compares cumulative minted units to `epoch.totalClaimSupply`:

```964:983:contracts/vault/modules/CreatorOVaultCoreModule.sol
    function mintImpairmentClaim(uint256 epochId, address account, uint256 amount, bytes32[] calldata proof)
        external
        onlyDelegateCall
    {
        if (account == address(0)) revert ZeroAddress();
        if (amount == 0) revert InvalidAmount();
        ImpairmentEpoch storage epoch = impairmentEpochs[epochId];
        if (epoch.status == ImpairmentEpochStatus.None) revert InvalidImpairmentEpoch(epochId);
        if (epoch.status != ImpairmentEpochStatus.Finalized && epoch.status != ImpairmentEpochStatus.Resolved) {
            revert InvalidImpairmentTransition(epochId);
        }
        if (impairmentClaimMinted[epochId][account]) revert ClaimAlreadyMinted(epochId, account);
        bytes32 leaf = keccak256(abi.encode(epochId, account, amount));
        bool valid = MerkleProof.verify(proof, epoch.snapshotRoot, leaf);
        if (!valid) revert InvalidClaimProof(epochId, account);
        if (impairmentClaims == address(0)) revert RecoveryEscrowNotConfigured();

        impairmentClaimMinted[epochId][account] = true;
        ICreatorOImpairmentClaims(impairmentClaims).mintFromVault(account, epochId, amount);
    }
```

`CreatorOImpairmentClaims.mintFromVault` only increments its own counter; no cap check:


### State available for caps

| Location | Variable | Purpose |
|---|---|---|
| `CreatorOVaultModuleStorage` / epoch struct | `totalClaimSupply` | Merkle epoch denominator (set in `proposeImpairmentRoot`) |
| `CreatorOImpairmentClaims` | `totalSupply[epochId]` | Cumulative ERC-1155 minted per epoch |
| `ImpairmentEpoch` | `totalRecovered`, `totalClaimed` | Vault-side recovery accounting |
| `CreatorORecoveryEscrow` | `recoveredByEpochAsset[epochId][asset]` | Notified recoveries |
| `CreatorORecoveryEscrow` | `claimedByEpochAsset[epochId][asset]` | Escrow payouts (uncapped vs recovered) |

A natural mint cap: `CreatorOImpairmentClaims.totalSupply[epochId] + amount <= epoch.totalClaimSupply` (readable via `ICreatorOImpairmentClaims(impairmentClaims).totalSupply(epochId)`).

A natural claim cap: `claimedByEpochAsset[epochId][asset] + amount <= recoveredByEpochAsset[epochId][asset]` in escrow, or vault-side `epoch.totalClaimed + amountOut <= epoch.totalRecovered` (vault already tracks those in `claimImpairmentRecovery` at 1007 but does not cap escrow calls).

## 3. H-1 — `notifyImpairmentRecovery` bypasses `coinBalance` tracking

### Raw transfer, no `_syncCoinBalance` / `_pushCreatorCoinExact`

```985:995:contracts/vault/modules/CreatorOVaultCoreModule.sol
    function notifyImpairmentRecovery(uint256 epochId, uint256 amount) external onlyDelegateCall {
        ImpairmentEpoch storage epoch = impairmentEpochs[epochId];
        if (epoch.status != ImpairmentEpochStatus.Finalized && epoch.status != ImpairmentEpochStatus.Resolved) {
            revert InvalidImpairmentTransition(epochId);
        }
        if (impairmentRecoveryEscrow == address(0)) revert RecoveryEscrowNotConfigured();
        IERC20(epoch.recoveryAsset).safeTransfer(impairmentRecoveryEscrow, amount);
        ICreatorORecoveryEscrow(impairmentRecoveryEscrow).notifyRecovery(epoch.recoveryAsset, epochId, amount);
        epoch.totalRecovered += amount;
        emit ImpairmentRecoveryNotified(epochId, epoch.recoveryAsset, amount);
    }
```

Contrast with the tracked outbound path:

```572:580:contracts/vault/modules/CreatorOVaultCoreModule.sol
    function _pushCreatorCoinExact(address to, uint256 amount) internal {
        IERC20 coin = _creatorCoin();
        uint256 beforeBal = coin.balanceOf(address(this));
        coin.safeTransfer(to, amount);
        uint256 afterBal = coin.balanceOf(address(this));

        uint256 spent = beforeBal - afterBal;
        if (spent != amount) revert TransferAmountMismatch(amount, spent);
        coinBalance = afterBal;
    }
```

### How `totalAssets()` / `coinBalance` work

- **Tracked variable:** `coinBalance` in module storage (`CreatorOVaultModuleStorage.sol` line 70).
- **Sync helper:** `_syncCoinBalance()` reads `balanceOf(address(this))` and writes `coinBalance`:

```555:559:contracts/vault/modules/CreatorOVaultCoreModule.sol
    function _syncCoinBalance() internal returns (uint256 actual) {
        IERC20 coin = _creatorCoin();
        actual = coin.balanceOf(address(this));
        coinBalance = actual;
    }
```

- **`totalAssets()`** sums **`coinBalance`** (not live `balanceOf`) plus non-impaired strategy assets:

```219:231:contracts/vault/modules/CreatorOVaultCoreModule.sol
    function totalAssets() public view onlyDelegateCall returns (uint256) {
        // FIX: L-06 — use tracked coinBalance instead of live balanceOf to prevent donation attacks
        uint256 total = coinBalance;

        uint256 len = strategyList.length;
        for (uint256 i; i < len; i++) {
            address strategy = strategyList[i];
            if (activeStrategies[strategy] && !strategyImpaired[strategy]) {
                total += _getStrategyAssetsSafe(strategy);
            }
        }

        return total;
    }
```

(Same pattern in monolithic `CreatorOVault.sol` at 927–940 and `_syncCoinBalance` at 1269–1272.)

### Guards / caps on `notifyImpairmentRecovery`

- **No zero-amount guard** (`amount == 0` not reverted).
- **No check** that `amount <= coinBalance` or that `epoch.recoveryAsset == creatorCoin`.
- **No `_pushCreatorCoinExact`** — when `recoveryAsset` is the creator coin, tokens leave the vault but `coinBalance` stays inflated → **`totalAssets()` overstates idle assets** until something else syncs.
