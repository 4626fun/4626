## Why greenfield (not another shell hot-swap)

v1.16.1 fixed drift via hot-swaps (Phase3 automation helper, AMOE router wiring). A v1.18.0 greenfield gives:

- Fresh `Registry4626`, `LotteryManager4626`, `VRFConsumer4626`, `SolanaBridgeAdapter`, bytecode store, CREATE2 deployer, and batcher shell in one epoch tag
- Correct `PROTOCOL_AUTOMATION_SAFE` immutables from deploy scripts (no copy-from-old-Phase3 bug)
- Fresh `LotteryAmoeRouter` v3 deployed + wired to the new manager in the same session
- Clean deprecation boundary for v1.16.1 addresses in `docs/reference/addresses.md`

## Custody model (who signs what)

| Step | Signer | Notes |
|------|--------|-------|
| CREATE / CREATE2 broadcast | Admin EOA (`PRIVATE_KEY` → `0xB05Cf0…`) | `forge script --broadcast`; owns registry/manager/router after `DeployInfrastructure` |
| Batcher wiring (`wireDeploymentHelpers`, `setPhase1Module`, Solana/OVault config) | **Protocol treasury Safe** (`0x7d429e…`) via `_safeExec` | Cold custody lane — **not** the forge deployer |
| Phase 3 Charm `manager` / Ajna `admin` immutables | **Protocol automation Safe** (`0x08f0875…`) | Set in deploy env — **never** treasury |
| AMOE allowlist/ledger publisher | Canonical CSW (`0xAb6d5…`) | Set on router post-deploy |

Do **not** attempt to make the cold treasury Safe the forge `msg.sender` for CREATE2 deploys — scripts are built for EOA broadcast + Safe wiring.

## Phase 1 — Broadcast greenfield infra

```bash

./script/run-v1180-greenfield-cutover.sh
# Post-broadcast: ./script/validate-greenfield-handoff.sh tmp/base-v1.18.0-handoff.env
```
