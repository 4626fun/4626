## Dry-run

Local fork dry-run uses `v1.14.0-dryrun` as the tracker namespace while preseed identity normalizes to `v1.14.0`, so AKITA `4626/4626` vanity applies without manual grinding:

```bash
pnpm -C frontend run dev:deploy-dry-run
```

By default the dry-run runner deploys a fresh local `DeploymentBatcher` + `Phase1Module` onto the fork (`DEPLOY_DRY_RUN_USE_LOCAL_BATCHER=1`) because the live batcher shell bytecode can fail Phase 1 delegatecall against the current module ABI.

## Retry guidance (Phase 1 partials)

If Phase 1 previously partially deployed for the same creator+version tuple:

1. Hard-refresh app/runtime.
2. Use a fresh deployment version namespace (`v1.14.0` or `v1.14.0-*`).
3. Confirm live batcher wires the v1.14.0 v3 Phase1Module and store seed checks pass.
4. Re-run deploy (e.g. `?deploymentVersion=v1.14.0-v18wl` for grounded AKITA vanity).
