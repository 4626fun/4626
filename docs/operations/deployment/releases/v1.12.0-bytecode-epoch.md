## On-chain operator steps

### 1. Seed bytecode store (chunked)

```bash
export UNIVERSAL_BYTECODE_STORE=0x8B51E6784A0C6681F5de25bAC4f9B2fDCEDE72b4
export BASE_RPC_URL=<paid Base RPC>
export PRIVATE_KEY=<protocol treasury signer>

forge script script/SeedUniversalBytecodeStore.s.sol:SeedUniversalBytecodeStore \
  --rpc-url "$BASE_RPC_URL" --broadcast
```

Use `SEED_OFFSET` / `SEED_LIMIT` for batched runs if gas limits bite.

### 2. Upgrade Phase 3 helper (hot-swap)

`protocolTreasury` is a 1-of-n Safe — deploy the helper from an EOA, then wire via Safe:

```bash
export DEPLOYMENT_BATCHER=0xa99058f424FB3ACC639F59355C65C40149030651

forge script script/DeployDeploymentBatcherPhase3HelperOnly.s.sol:DeployDeploymentBatcherPhase3HelperOnly \
  --rpc-url "$BASE_RPC_URL" --broadcast

pnpm -C frontend exec tsx scripts/ops/wire-phase3-helper-safe.ts \
  --phase3-helper <NEW_PHASE3_HELPER_FROM_HANDOFF>
```

### 2b. Authorize Phase 3 helper on CREATE2 deployer

Phase 3 CREATE2 deploys run from `phase3Helper` (external call), not the batcher shell. After wiring the new helper, the create2 deployer owner must call:

```bash
pnpm -C frontend exec tsx scripts/ops/authorize-phase3-helper-create2.ts
pnpm -C frontend exec tsx scripts/ops/verify-phase3-helper-create2-auth.ts
```

Ensure root `.env` `DEPLOYMENT_BATCHER` matches `0xa99058…` (not the deprecated `0x16aEA8…` shell).
