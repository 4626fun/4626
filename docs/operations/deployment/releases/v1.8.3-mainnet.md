## Preflight Checklist

Run these from the repo root before the real broadcast:

```bash
set -a
source .env
set +a

test -n "$PRIVATE_KEY"
test -n "$BASE_RPC_URL"
test -n "${ETHERSCAN_API_KEY:-${BASESCAN_API_KEY:-}}"

DEPLOYER_ADDRESS=$(cast wallet address "$PRIVATE_KEY")
cast chain-id --rpc-url "$BASE_RPC_URL"
cast balance "$DEPLOYER_ADDRESS" --ether --rpc-url "$BASE_RPC_URL"
```

Expected:

1. `cast chain-id` returns `8453`
2. the deployer address matches the wallet you intend to use for the release
3. the balance is high enough for the full shared/global deploy, deterministic v2 deploy, and bytecode-store seeding

Repo-side verification before broadcast:

```bash
forge build --skip test --skip script
./script/generate_bytecode_manifest.sh v1.8.3
bash ./test/v183-release-target-guard.sh
forge test --match-contract RegistryDefaultScriptsTest
forge test --match-contract SeedCreatorRegistryConfigTest
```

## Broadcast Command Sequence

The canonical live rollout command is:

```bash
./script/deploy-base-full-release.sh
```

This wrapper:

1. loads `.env`
2. deploys the fresh shared/global layer
3. hands those addresses into the deterministic v2 deployer
4. seeds the bytecode store automatically
5. prints the shared/global artifact path and handoff env path for post-deploy follow-up

If you want to pin the epoch explicitly in the same shell:

```bash
export DEPLOYMENT_EPOCH_TAG=v1.8.3
./script/deploy-base-full-release.sh
```

## Post-Broadcast Follow-Up

After a successful live broadcast:

1. capture the shared/global and deterministic tx hashes, block numbers, timestamps, and final addresses
2. replace this packet's pre-broadcast status with the real live broadcast details
3. refresh `deployments/base/contracts/**/*.json` from the new live addresses and current ABIs
4. update `.env.example`, `frontend/.env.example`, and `frontend/src/config/contracts.defaults.ts` from the old live addresses to the new `v1.8.3` addresses
5. re-run the release guard and manifest verification after the address cutover

1. restore `DEPLOYMENT_EPOCH_TAG` defaults to `v1.8.2`
