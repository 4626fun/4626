- **Dune analytics is server-only.** `DUNE_API_KEY` lives on Vercel/server env only (`frontend/server/_lib/dune/duneApi.ts`); browser calls `GET /api/analytics/dune?metric=…` or `?probe=1` (`frontend/api/_handlers/analytics/_dune.ts`). SQL templates: `frontend/server/_lib/dune/duneMetricSql.ts`. Probe: `pnpm -C frontend exec tsx scripts/ops/dune-probe.ts`. Runbook: `docs/operations/dune-analytics-runbook.md`. Integrator token manifest stub: `/data/explore-assets-manifest.json`.

- **Explore 30D sparklines:** `resolveCoinPriceSparkline` reads Uniswap V4 subgraph (`PoolDayData`) first with Zora swap fallback; `/api/zora/explore` inline-hydrates missing sparklines so first paint can skip a second `/api/zora/exploreSparklines` round-trip; hot-sync cron precompute is gated by `CREATOR_METRICS_SPARKLINE_PRECOMPUTE_ENABLED` / `_BUDGET` / `_CONCURRENCY` on Vercel.

- **Scheduled `zora_profiles` refresh keeps Looker/analytics snapshots current.** `GET|POST /api/v1/zora-profiles/refresh-cron` (Vercel cron `15 */6 * * *`) upserts cached market/volume/holder fields from the Zora explore API, runs bounded wallet enrichment, and reconciles `is_in_csw_index`; gate with `ZORA_PROFILES_REFRESH_ENABLED=1` on production. Monitor via `v_zora_profiles_refresh_freshness`; runbook: `docs/operations/zora-profiles-refresh-runbook.md`.

- **`/api/onboarding/preview-agent-owner` now has a CSW-self proof path via ERC-1271.** When `connectedEoa`/`connectedAddress` equals `cswAddress`, callers can provide `ownershipProof { issuedAtMs, message, signature }`; the handler enforces a short freshness window and validates `isValidSignature` (`0x1626ba7e`) against a deterministic message template. The prior EOA-owner path remains unchanged.

- `docs/operations/coinbase-smart-wallet-capabilities.md` is the workspace reference for Coinbase/Base Account SDK capability snapshots; the SDK 2.5.1 E2E pass recorded `eth_signTypedData_v4` and `spendPermission.fetchPermissions()` as working while `personal_sign` may time out in that demo environment.

- **The Zora outreach pipeline in `indexer/` now includes name/profile enrichment and export scripts.** `pnpm -C indexer names` resolves Basename/ENS into `zora_csw_owner_class`, `pnpm -C indexer zora-profiles` adds Zora handles/display names/creator-coin addresses, and `pnpm -C indexer export:outreach` emits ranked triple-signal CSV/JSON cohorts under `indexer/exports/` for outreach planning. The operator dashboard surface is Google Sheets driven by `indexer/scripts/sheetsOutreachSetup.gs.js` (Google Apps Script) — Sheets is the preferred operating surface over Looker Studio, with Notion sync as an optional destination rather than a replacement.

- **Zora Explore list data does not expose canonical ERC-20 ticker/name fields for creator coins.** In `indexer` workflows, `name`/`symbol` from list responses can mirror creator handles (for example `jessepollak`) instead of on-chain token metadata (for example `$jesse`), so ticker/name truth must come from on-chain `name()`/`symbol()` reads (`fix-profile-metadata`) before outreach ranking/export.

- **AlfaClub chat bridge supports runtime JWT rotation without process restart.** `alfaclub_runtime_secret` stores short-lived JWT state, admin route `POST/GET/DELETE /api/v1/alfaclub/chat-token` manages rotation metadata, and chat bridge ticks prefer DB token with fallback to `ALFACLUB_CHAT_JWT`. Privy refresh tokens are single-use: once a refresh succeeds, trust the newly rotated DB values; if a later refresh fails, mint a fresh browser triplet instead of reseeding stale clipboard tokens over the live DB row. **The Vercel cron `/api/v1/alfaclub/chat-token-refresh` is the single canonical rotation owner** — the Railway in-process refresher stays disabled (`ALFACLUB_CHAT_PRIVY_REFRESHER_ENABLED` off) so two runtimes never race over the single-use refresh token. Supabase is storage only; the actual refresh is an HTTP call to Privy's sessions endpoint (`privyTokenRefresher.ts`). Ops repair is `pnpm -C frontend ops:alfaclub:repair-chat-token ./triplet.json`, which seeds via `CRON_SECRET`, runs refresh + bridge checks, and deletes the local triplet by default; production smoke should fail on disabled bridge, `success=false`, or a newer refresh failure than success.

- **Pinata CLI auth in this workspace is TTY-gated.** Non-interactive `pinata auth ...` attempts from agent shells can hang/fail; run interactive `pinata auth` once in a user terminal before CLI automation (`agents list/get/config/channels`) and then proceed with scripted ops.

- **Telegram link-readiness command surface is `/status` (not `/linked`).** Command registry/webhook/menu callback wiring uses `head: 'status'` and `menu:status`, with no backward-compat alias.

- **Single-agent XMTP runtime now enforces one active DB per env.** In `frontend/server/agents/eliza/index.ts`, `makeDbPath({ enforceSingleFileForEnv: true })` archives stale `xmtp-<env>-*.db3` files and orphaned sidecars (`-wal`, `-shm`, `.sqlcipher_salt`) so startup keeps a single active local database path.

- **Current release-target validation lives in `test/current-release-target-guard.sh`.** `test/v183-release-target-guard.sh` is only a deprecated compatibility wrapper; active operator docs/checklists should call the current guard path so release checks validate the live split Phase-1 stack rather than historical v1.8.3 assumptions.

- Local dev URL stability expectation: keep app flows on `localhost:5173`/`localhost:5174`; redirects to random localhost ports are treated as regressions to investigate. On WSL2, if `localhost:5174` fails from a Windows browser, try `127.0.0.1:5174` first.

- **CreatorOVaultWrapper advanced wrap/unwrap paths share the cooldown invariant.** Advanced `wrap()` must record cooldown and advanced `unwrap()` must enforce it; tests that use the advanced path should advance time explicitly rather than bypassing cooldown expectations.

- **CreatorOVaultStrategiesModule hostile-withdraw accounting must include negative idle deltas.** When a failed strategy leg drains idle vault balance, increase the remaining withdrawal deficit before trying the next healthy strategy so final user transfers do not hit `InsufficientBalance`.

- **Production orchestrator runs as its own systemd unit beside the provisioner.** Seed only current KPR env keys; do not copy or normalize retired adapter/Twin secrets. After changing `SOLANA_ORCHESTRATOR_*` on Vercel, redeploy production so API routes pick up the values.

- **When `SOLANA_ORCHESTRATOR_URL` is missing on Vercel, solana reconcile checkpoints stay `skipped_unconfigured`** and the control-plane operation should complete as `manual_review` (not `failed`); do not point `SOLANA_ORCHESTRATOR_URL` at the provisioner `/provision` URL.

- **Solana route provisioner imports bridge helpers from `frontend/server/_lib/onchain/`** (`solanaBridgeCliRunner`, etc.) — `../_lib/` paths break production `solana-provisioner` startup with `ERR_MODULE_NOT_FOUND`.

- **X API Pay-Per-Use billing** is **per resource returned**, not a flat per-HTTP-call fee — credits deduct by endpoint plus posts/users/following rows returned (developer console is source of truth). Webhook follow auto-award avoids follow read charges; repost/comment verify only on user click (~1–2 capped timeline reads each).

- **Solana `creator-share-hook` C-01 mainnet upgrade + verification:** run `programs/creator-share-hook/scripts/upgrade-mainnet.sh` (dry-run default; `--execute` when funded) — upgrade authority needs **≥ ~3 SOL** for the temporary deploy buffer (mostly refunded); **deployed 2026-07-03** slot 430461604 (tx `5EyDaFfa…GuTqB`); **solana-verify** verified via [`4626fun/creator-share-hook-verifiable` @ `b092227`](https://github.com/4626fun/creator-share-hook-verifiable/tree/b092227) with `--cargo-build-sbf-args="--tools-version v1.52"`; after upgrade set **`SOLANA_HOOK_IX_SCHEMA=canonical`** in orchestrator env (`legacy` ix discriminators mismatch on-chain); keep **`SOLANA_ORCHESTRATOR_RELAY_ENTRIES_ENABLED=0`** until B2 smoke (runbook: `docs/_internal/operations/solana/creator-share-hook-mainnet-upgrade.md`).

- **Solana B2 trade fee is on the Meteora DLMM pool, not Token-2022.** Keep mint transfer fee / CreatorConfig `fee_bps` at 0. Canonical pool create uses `FEE_BPS=690` + `CollectFeeMode.OnlyY` (`kpr solana:create-dlmm-pool`); mainnet seed requires explicit `FEE_OWNER` via `solana:seed-dlmm-liquidity`. Claim jackpot-bound fees with orchestrator action `claim_dlmm_fees` (`SOLANA_ORCHESTRATOR_CLAIM_DLMM_FEES_ENABLED=1`) — fail-closed if `SOLANA_DLMM_FEE_OWNER` ≠ on-chain position `feeOwner`; do **not** use `settle_fees` for this path. Forward claimed WSOL to Base with `forward_dlmm_fees` (`SOLANA_ORCHESTRATOR_FORWARD_DLMM_FEES_ENABLED=1`): Jupiter best-path WSOL→■ (DLMM fallback via `SOLANA_FORWARD_SWAP_MODE=dlmm`), Jito/private submit when `JITO_SUBMIT_ENABLED=1`, helper-gated LZ OFT (`SOLANA_OFT_FORWARD_HELPER`), then hub `receiveBridgedFees`. Base V4 sell-tax WETH uses gauge `processWETHFeesWithRoute` (allowlisted router calldata → ■, no `buyFeeBps`; keeper-only + private relay). B2 preflight also checks `meteora_protocol_position_fee_owner` against `SOLANA_B2_JACKPOT_FEE_OWNER` + `SOLANA_B2_PROTOCOL_POSITION_OWNER`. Open third-party LPs keep their own fee share.

- **Solana keeper orchestrator `POST /reconcile` requires three body fields:** `action`, `workflow`, and `checkpointKey` — requests with only `action` return a checkpoint gate error, not a workflow failure.

- **Vultr Solana ops host:** production checkout at **`/opt/4626`**; orchestrator systemd unit often runs as **`root`** (not assumed `app4626` user from `kpr/deploy/install-systemd.sh`) — checkpoint/state ownership must match service `User=`; **`tsx` binds `:8789` ~6s after `systemctl restart`** — wait before `curl /healthz` or nginx returns 502; env at `/etc/4626/solana-keeper-orchestrator.env`; `kpr/deploy/seed-solana-orchestrator-env.sh --hook-schema auto` must use **`grep`** not **`rg`** (Vultr lacks ripgrep).

- **Solidity contract naming policy (locked):** shared protocol singletons/global authorities use `*4626` suffix (`Registry4626`, `VaultFactory4626`, `OVaultFactory4626`, `CharmStrategy4626`); lane contracts keep `Creator*`/`Agent*` prefix without 4626; generic infra/libs have no lane prefix unless they are protocol authorities; interfaces mirror implementation naming where practical. Authoritative layout + lane-parity rules: `contracts/README.md`.

- **Contracts lane parity (`agent/` vs `creator/`):** folders are intentionally not identical — (1) thin inheritance overlays (`AgentOVault extends CreatorOVault`; lane-shared modules under `contracts/shared/vault/`, `shared/distribution/VaultShareBurnStream`, `shared/vault/recovery/`); (2) four copy-renamed fork pairs (`AgentShareOFT`/`CreatorShareOFT`, wrappers, gauge controllers, revenue routers) that must stay logic-identical — mirror edits in the same PR; CI: `pnpm guard:lane-contract-parity` (`scripts/check-lane-contract-parity.mjs`); (3) intentionally divergent oracles and lane-only policy/tax contracts.

- **AMOE ZK production path (post July 2026 security remediation) requires explicit Vercel flags:** `AMOE_ZK_SUBMIT_ENABLED=1`, `AMOE_BURN_THEN_SUBMIT_REQUIRED=1`, `AMOE_LEDGER_PUBLISHER_ENABLED=1`, `AMOE_ALLOWLIST_PUBLISHER_ENABLED=1`, and `AMOE_REFUND_CRON_ENABLED=1` — paths fail closed when flags or `LOTTERY_AMOE_ROUTER` / publisher keys are unset.

- **Shovel protocol indexer (Railway `4626-shovel-indexer`):** Index Supply Shovel writes Base mainnet protocol events into Supabase (`indexer/shovel/`). Lottery APIs (`/api/v1/lottery/recentWinners`, `recentEntries`) read the index with RPC fallback. Tip gating must use **`MIN(MAX(src_num) per required integration)`** with required-integration counting — not raw `MIN(src_num)` across historical rows and not `MAX` across integrations (incomplete windows). Keep unused `protocol_*` integrations disabled (full ShareOFT `Transfer` logs hit eth_getLogs 20k caps / converge-retry loops). Default `SHOVEL_BATCH_SIZE` is **200**. Lag-aware `/health` is for ops observability — Railway deploy readiness does not continuously monitor `/health`, so post-deploy 503s do not imply restart loops. Local `railway` CLI may be linked to the shovel service instead of Hermit; confirm the linked service before deploy commands.
