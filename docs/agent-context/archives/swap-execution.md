## Learned User Preferences

- Do not redesign `/swap` into a new layout — keep the Uniswap-like information architecture and only improve hierarchy, spacing, microcopy, states, accessibility, and responsiveness within it. The token selector modal may use Uniswap-style search, quick-pick chips, per-row balances, and clear loading/empty states without changing swap-page IA; pin AKITA under a **Trending** section when present; use collapsible **Creator coins** vs **Content coins** groupings plus an optional **Hide balances under $0.01** dust filter; use the creator/display name as the primary row label with on-chain symbol + shortened address as secondary (not Zora handle text that disagrees with ERC-20 metadata), and surface Zora coins the execution wallet already holds in a dedicated holdings section. Prefer token/protocol logos (Coinbase, Base, Uniswap) over text labels for wallet/chain affordances — Base chain selector should use the square Base logo shape without redundant "Base" text; format sub-cent prices with Uniswap-style significant-digit rules rather than long decimal tails. Surface a "Powered by Uniswap" mark, keep wallet/address rows to one line, and use a draggable percent slider (DeFiLlama-style) rather than 25/50/75/100 buttons. After a successful swap, show a persistent compact top-right `SwapCompletionNotice` with a BaseScan link — do not leave users without on-chain confirmation when the transaction lands — and refresh sell/buy balances on the swap modal (and token-selector holdings) once the tx is **mined/confirmed** (do not refetch solely on a pre-confirmation submitted hash for `eoaDirect` / `canonicalDirect`). Do not surface internal bundler slippage-retry ladder copy — user-selected slippage should stay authoritative. Skip unverified-token warnings for Zora-indexed creator/content coins. Do not show Permit2 wallet-confirm copy when the Privy embedded EOA auto-signs. Swap Details should match Uniswap fidelity: honest output USD (never mirror input), multi-hop route preview with pool fee tiers, and accurate gas USD / price impact.

- Prefer **`shareoft-mesh`** over **`share-mesh`** for shared folder/import paths naming ShareOFT mesh arms (CCA launch + post-CCA Uniswap V4 LP) — clearer product term than vague "share mesh".

## Learned Workspace Facts

- Canonical project framing: 4626 is not only vault + swap infrastructure; it includes a core lottery/rewards system and a **ve(3,3)-inspired** incentive model that favors **share-token burn/value-capture mechanics** over inflationary token emissions.

- `/api/uniswap/quote` and `/api/uniswap/swap` proxy endpoints require an authenticated 4626 session principal; `useSwapExecution` gates quote requests behind session hydration to avoid 401 errors. `/swap` quote display is read-only and should require session + execution address, not full `executionReady`; submit/build remains gated on `executionReady`.

- **Paymaster swap simulation recognizes Zora Universal Router as `swapRouterKind: 'zora-universal'`.** Keep paymaster router-kind detection aligned with client swap build paths when adding new Zora or Universal Router execution lanes.

- `frontend/src/lib/aa/` and `frontend/src/lib/uniswap/` are cross-cutting client utilities with multiple feature consumers; keep them under `src/lib/` rather than relocating into individual `src/features/*` folders.

- `/swap` wallet gating uses a pure state machine `deriveSwapConnectGate` in `frontend/src/lib/swap/connectGate.ts` plus a `SwapConnectGate` component; the connect CTA uses `<Button variant="primary">` from `@/components/ui/Button`, and the wallet-required path uses wagmi `connectAsync` with the shared preferred-connector helper instead of Privy `connectWallet`/`login`. When provider-collision mode hides injected wallets, filter Rabby/MetaMask/injected connectors before choosing the preferred connector so Coinbase/Base App remains the safe path. `<SwapCard>` only mounts when the gate resolves to `ready`. Balance labels in canonical mode read from the canonical CSW (`profiles.csw_address`), which is also the default `canonical4337` execution sender.

- Sponsored canonical/paymaster swaps cannot sell native ETH directly because the paymaster path cannot sponsor `tx.value`; `/swap` blocks that embedded canonical path and offers `Switch Sell to WETH` so the sponsored ERC-20 approval/swap path can continue. Native ETH sells still require a funded external signer or explicit wrapping first.

- **Embedded canonical swap fallback is dev-only.** `frontend/src/lib/tx/txRouter.ts` keeps production strict (`canonical4337` required) but now permits a local/manual fallback to `canonicalDirect` only when `VITE_ALLOW_EMBEDDED_CANONICAL_DIRECT_FALLBACK=1` or host is `localhost`/`127.0.0.1`/`::1`; this unblocks local paymaster outages without weakening production sponsorship policy.

- **`TRANSFER_FROM_FAILED` during sponsored canonical swap gas simulation usually means the CSW has 0 WETH while the simulator runs only the Uniswap swap-proxy leg (`0x2894adf9`) without batched `WETH.deposit()`.** Skip `simulateTransaction` when a sponsored native-ETH sell batches wrap+approve+swap (`shouldSimulateSwapTransaction` in `useSwapExecution.ts`); map the error to insufficient-funds copy in `error.ts`; run `assertSwapSpendBalancePreflight` on the execution wallet before `eth_sendUserOperation`.

- **canonical4337 AA25 (invalid account nonce) is an in-flight UserOp collision, not a signer bug.** CSW UserOps use `ownerIndex` as the EntryPoint nonce sequence key — sparse high slots (e.g. owner 18) are normal. On bundler AA25, `coinbaseErc4337.ts` must wait for the sequence to advance (`waitForEntryPointNonceAdvance`) instead of re-submitting the same nonce; owner-index scans in `coinbaseErc4337Owners.ts` wrap reads with `readContractWithRpcRetry` for RPC 429 resilience.

- **`/swap` from the 4626 canonical CSW:** requires sell-token balance on that CSW; gate automation to active allowlisted owner signers only. Zora `canonical4337` sells use a single router `execute` call; revert `0x2c4029e9` is CSW `ExecutionFailed` wrapping inner Zora Universal Router failure (Permit2, slippage, balance) — not AA25. Sparse owner slots are normal (`ownerCount` ≪ `nextOwnerIndex`, e.g. signer at slot 18).

- **canonical4337 must fail fast when preflight simulation says the inner call would revert.** When `coinbaseErc4337.ts` preflight reports `ExecutionFailed` or another deterministic router revert, abort before `estimateUserOperationGas` and transient retries — do not loop gas estimation on a UserOp that preflight already proved would revert.

- **`canonical4337` swap-router gas floors and bundler estimate policy:** apply `callGasLimit` floors to Zora execute, Uniswap UR `0x3593564c`, swap-proxy execute, and multi-call wrap/approve/swap batches — not Zora-only. Bundler `estimateUserOperationGas` advisory skip applies to stub-signature `InvalidContractSignature` (`0xb0669cbc`) on echoed **`execute`** and batched **`executeBatch`** (`0x34fcd5be`) calldata when direct preflight passed; **`ExecutionFailed` (`0x2c4029e9`) at estimate is a real router revert** (slippage, Permit2, thin pools) even when production `eth_call` preflight passed — do not advisory-skip and submit. **`paymaster proxy internal error` is an `/api/paymaster` handler crash** (`paymaster_proxy_internal_error`), not sponsorship denial — do not classify it as policy rejection or retry unsponsored canonical swaps.

- **canonical4337 `executeBatch` execution reverts get per-leg replay, ladder abort, and a prefund-gated unsponsored fallback.** `replayExecuteBatchPerLeg` in `coinbaseErc4337.ts` replays wrap/approve/swap prefixes via production `eth_call` to pinpoint the failing leg and map it to user copy (Permit2 `InvalidNonce`, slippage, insufficient funds); deterministic execution reverts abort the verificationGasLimit retry ladder (`shouldAbortUserOpGasLadder`) instead of resubmitting ~6 identical UserOps; the unsponsored fallback is skipped for swap-heavy execution reverts and otherwise gated by `assessUnsponsoredPrefundFeasibility` (`walletBalance >= callValue + maxGasCost`). `simulateSmartWalletCalls` must not report first-leg-only success for multi-call batches.

- **Zora V4 hooked creator-coin pools quote at 10% slippage by default** (Zora's own `getQuoteStrict` sends `slippage: 0.1`). The canonical auto-slippage floor in `swapAutoSlippage.ts` and the CSW escalation ladder in `zoraTradeApi.ts` start at 10% (10 → 15 → 20) — do not lower the floor back to 5%, which burns retries in the "slippage too tight" loop. Also, the CDP paymaster denies bare approve-only UserOps (`request denied - approve_only_not_allowed`) — sponsored approvals must be batched with the swap leg.

- Uniswap pool-history fetch falls back to Zora `getCoinSwaps` via `/api/zora/coinHistory` (handler `frontend/api/_handlers/zora/_coinHistory.ts`) to derive OHLCV candles when the Uniswap subgraph has no data points; the fallback is built into `fetchPoolHistory` in `frontend/server/_lib/uniswap/hooks.ts`, and the endpoint must stay registered in both `_routes.zora.ts` and the Vite dev proxy in `frontend/vite.config.ts`.

- **PayoutRouter non-creator-coin conversion swaps to ShareOFT then unwraps to vault shares** (`swapPathToShareOFT`, balance-delta unwrap after ShareOFT buy fee). Direct creator-coin payouts still deposit via `vault.deposit(creatorCoin)`. Deploy must whitelist the router on the wrapper **before finalize transfers wrapper ownership** (`DeploymentBatcher.whitelistPayoutRouterOnWrapper`) so atomic swap+unwrap bypasses wrapper cooldown. Harvest V3 quotes apply a ~6.9% ShareOFT buy-fee haircut before slippage; never run with zero min-out.

- **Local AKITA tend/report uses ERC-4337 on the canonical CSW, not the Vercel EOA bridge.** Set `KPR_USE_KEEPER_HTTP_BRIDGE=0` with `KPR_ERC4337_ENABLED=true` and `KPR_ERC4337_*` (not legacy `CRE_ERC4337_*` — KPR no longer reads `CRE_*`) so `vault-keeper` signs via the canonical CSW owner lane (CDP bundler/paymaster). `./scripts/ops/sync-kpr-env-from-vercel.sh` syncs `KPR_API_KEY`, RPC, and orchestrator URLs only — **not** `KPR_PRIVATE_KEY`; keep keeper signing keys local or set explicitly on Vercel.

- **Privy unified-stack embedded wallets with `owner_id` need user authorization signatures on Wallet API RPC.** A `401` on `privy.4626.fun/api/v1/wallets/.../rpc` during canonical swap Permit2 / raw-digest signing is not fixed by access-token refresh alone — attach `privy-authorization-signature` from Privy's `useAuthorizationSignature` hook via `privyAuthorizedWalletRpc.ts` (`privyAuthorizedWalletSecp256k1Sign`), wired through `useSwapEmbeddedEoa.ts` and optional `signSecp256k1Digest` in `signRawEcdsaDigest.ts`. Server-side `PRIVY_WALLET_AUTHORIZATION_KEY` signing (`privyWalletApi.ts`) is a separate lane for automation wallets, not login embedded EOAs.

- **Zora wallet holdings use three coin types (`CREATOR` | `CONTENT` | `TREND`).** Normalize via `frontend/src/lib/zora/coinType.ts` (`normalizeZoraCoinType`) — do not bucket unknown or trend rows as creator coins; tray (`server/_lib/wallet/zoraWalletHoldings.ts`), account tray, and swap selector expose separate trend sections (`sectionTag: 'trend'`).

- **`/swap` token selector must combine vault index with Zora discovery.** Vault-only `/api/v1/explore/vaults` / `keepr_vaults` rows miss creator coins like AKITA; parallel Zora profile/coin resolution lives in `frontend/src/lib/swap/zoraTokenSearch.ts` with `$`/`@` stripped via `normalizeCoinSearchQuery`.

- **`/swap` Buy output display is quote-only.** The read-only Buy field must bind to `estimatedOut` (or post-success `swapCompletion.estimatedOut`), not wallet balance — empty-quote fallback to balance shows misleading `0` while quoting; show "Fetching quote…" while `busy === 'quote'`. Auto-quote effects that pause while signing must destructure `txState` from `useSwapExecution()` — referencing `txState` without pulling it from the hook crashes `/swap`.

- **Canonical swap submit latency:** after a passing Zora router `eth_call` validated at Review, skip the redundant CSW `execute()` simulation on submit — that path was the main multi-second stall on `canonical4337` sells.

- **Post-CCA vault completion order (canonical):** `sweepCurrency` → `migrate` (V4 pool init at clearing price, **no LP mint**) → `deployShareMeshLpManager` → `seedLpManager` → `seedRebalance` → keeper completion invariants → DB `settledAt`. The **10k LP reserve** in tests/docs is ShareOFT pre-funded on the launch arm at `launchAuctionWithReserve` (auction collateral, not Uniswap LP); tradable LP is seeded only after CCA via share-mesh steps. Per-vault `CreatorOracle` is part of the share-mesh completion story (CCA floor pre-auction, `setV4Pool` post-migrate, ongoing mesh/gauge pricing) — not a vault leg/strategy.
