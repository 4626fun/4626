- **Agent/Hermit Docker build context:** `frontend/Dockerfile.agent` runner must COPY `frontend/shared` (`site-config.json` — imported by `agentRegistration.ts`); `4626-keepr-agent` crashes without it. `frontend/Dockerfile.hermit` deps stage must COPY `frontend/server` plus `src/config`, `src/lib`, and `src/wallet` **before** `packages/server-core` `build.mjs` (re-export scan needs those sources).

- **Hermit creative drafts run on Vercel** through `POST /api/hermit/draft`; Railway calls that endpoint via `HERMIT_AGENT_*` and must not run a second creative model. Pinata remains an asset gateway only, not a Hermit agent runtime.

- **Hermit prod env on Vercel:** `vercel env pull` can show empty strings for encrypted production vars even when keys exist — verify `HERMIT_AGENT_CHAT_ENDPOINT`, `HERMIT_AGENT_BEARER_TOKEN`, `HERMIT_AGENT_PROVIDER`, and `ALFACLUB_HERMIT_COMMAND_ROOMS` with `vercel env run -e production`; if empty, remove and re-add via `vercel env add`, then production redeploy. E2E audit: `bash frontend/scripts/ops/audit-hermit-e2e.sh` (optional `--production-env --strict`).

- **`hermit.4626.fun` Telegram ingress must hit Vercel, not Railway.** `TELEGRAM_TO_ALFACLUB_INGRESS_HOST=hermit.4626.fun` is correct (hostname only); `POST /api/telegram/webhook` is served by Vercel project `akita-llc/4626`. If DNS points at Railway (`x-railway-edge`), Telegram gets 404 and Hermit relay never runs — add the subdomain on Vercel and point DNS there; keep Railway Hermit health on `*.up.railway.app`. The Hermit Telegram bot is **`@hermit4626bot`** with its webhook on `https://app.4626.fun/api/telegram/hermit-webhook` (aligned via `frontend/scripts/ops/setup-hermit-telegram-webhook.ts`, group privacy OFF), and its bot token env is **`HERMIT_TELEGRAM_BOT_TOKEN`** — renamed from `ALFACLUB_TELEGRAM_BOT_TOKEN`; do not reintroduce the old name. The Telegram Mini App link entry lives on `app.4626.fun/telegram/link`.

- **`chatBridge.ts` must lazy-load `executeDeterministicCommand`.** Eager import creates a circular dependency (`chatBridge` → `execute` → `alfaclub` → `chatBridge`) that crashes `/api/v1/alfaclub/chat-bridge-run` at module load (500) and silences `/alfa` in Hermit rooms like **1659** even when room env is correct.

- **Hermit AlfaClub room 1659 market context:** `room1659Market.ts` injects Hyperliquid snapshot data into Hermit command context; multi-room Hermit routing uses `ALFACLUB_HERMIT_COMMAND_ROOMS` (comma list, e.g. `1043,1659`) in `chatBridge.ts` — runbook `docs/design/room-1659-hermit-market-awareness.md`. **The HL snapshot must read the dedicated room portfolio wallet (the room's `walletAddress`), not the requesting sender** — `resolveRoom1659HyperliquidUserForSnapshot()` ignores `senderAddress` and delegates to `resolveRoom1659HyperliquidPortfolioUser()`. Room 1659 is a `one-to-many` Trading room, so sender-wallet snapshots show empty positions for almost every caller ("wrong address" / no-open-position regression); keep `/halp`, `/hermit`, and market-pulse pinned to the portfolio wallet.

- **Room 1659 `/halp` + `/position` wallet lanes:** show a **Wallet lanes** section with (1) **Room HL portfolio** (`resolveRoom1659HyperliquidPortfolioUser`), (2) **Virtual Arena execution** compact HL summary when different from the room wallet (prefers arena `hlApiWalletAddress`, falls back to `agentWalletAddress`), and (3) **operator wallet** — the AlfaClub posting address that owns the alert subscription (`formatRoom1659WalletLanesSection` in `positionReport.ts`).

- **Room 1659 Hermit HL alert scope:** `/hermit alert` in room 1659 stores subscriptions under scope `1659` (`ROOM_1659_ALERT_SCOPE` in `hermitAlertWallets.ts`) and monitors **room HL portfolio + Virtual Arena HL wallet** — not the sender's personal HL wallet; `positionAlertRunner.ts` evaluates both wallets per tick. Legacy `hyperliquid` scope outside room 1659 still monitors the sender wallet only.

- **Hermit liquidation alert threshold copy:** default "within 10%" means **mark→liquidation distance as % of estimated mark price** (`positionProximity.ts`), not position size, margin, or account equity — keep this phrasing in alert status, Telegram DMs, and `/hermit alert liq` help (`formatLiquidationThresholdLine` in `positionAlertStore.ts`).

- **Hermit Telegram alert linking:** DM delivery resolves profile-level via `telegram_user_links` JOIN `profile_wallets` on `profile_id` where `lower(pw.address)` matches the **operator wallet** (AlfaClub command sender), not the CSW address stored on the Telegram link row; `/halp` and alert status should show linked-Telegram state plus Mini App link → `/hermit alert` → `/hermit alert test` onboarding.

- **`/positions` is a social-signal trading surface** that overlays AlfaClub room chat (e.g. room 1659) onto a Hyperliquid-style candlestick chart with per-market position events. Page `frontend/src/pages/Positions.tsx` + `frontend/src/components/positions/*`; server data via `frontend/server/_lib/alfaclub/roomTimeline.ts` + API `GET /api/v1/alfaclub/room-timeline`. **Chat text is room-access-gated** (`resolveRoomChatViewAccess`): anonymous and signed-in viewers without access get candles/trades only (`chatEvents: []`). Access = FriendKey for the room (**held or staked**) **or** creator-coin / LP-equivalent via `room_access_policies` (AlfaCreatorKeyPool `quoteBuyKeys` today; Sudoswap ERC-1155/ERC-20 LP equivalence can extend that lane later). Same gate on `GET /api/v1/alfaclub/room-chat`. Do not re-open world-readable chat. **Markets must stay decoupled per pair** — never combine events across markets, and the selected market must drive the candles shown. Use **only real room/trade data — never fabricate events**, prices, or P/L.

- **Hermit OpenClaw Telegram hardening baseline:** keep `dmPolicy: pairing`, `groupPolicy: allowlist`, and no wildcard DM `allowFrom` on agent `x6bk3ima`; preserve this posture when applying model/runtime config updates.

- **Telegram → AlfaClub inbound relay is env-gated via `TELEGRAM_TO_ALFACLUB_*`.** `frontend/server/_lib/alfaclub/telegramToAlfaclubRelay.ts` posts configured supergroup/topic messages into `TELEGRAM_TO_ALFACLUB_ROOM_ID` (default `ALFACLUB_CHAT_ROOM_ID`) with `ALFACLUB_API_KEY` and skips the normal Telegram handler for that chat; AlfaClub → Telegram remains `ALFACLUB_TELEGRAM_RELAY_*`.

- **AlfaClub Cloudflare proxy auth shape:** only `GET /_health` is public without `x-proxy-secret`. Relayed API paths need `x-proxy-secret` aligned with `ALFACLUB_CHAT_API_PROXY_SECRET` / Worker `PROXY_SHARED_SECRET`. Worker body `{"error":"unauthorized"}` means bad/missing secret; upstream `No JWT token found` with a good secret means the proxy reached AlfaClub (JWT is DB/`chatBridge`, not local `ALFACLUB_CHAT_JWT`).

- **Arena backtest bar loading:** Hyperliquid exposes ~3.5 days of 1m candles per request; 90-day minute fidelity needs Supabase `backtest_market_bars_1m` via `pnpm -C frontend exec tsx scripts/cache-backtest-minute-bars.ts` (uses `backfill_window` when coverage below ~92%). Auto bar-size selection picks the finest interval with full-horizon coverage — until the cache fills, 90d runs resolve to **1h**. Runs via `POST /api/v1/alfaclub/backtest-run` (returns inline `series` + `resolvedInterval`); deploy-dry-run dev uses `localhost:5174/__api/v1/alfaclub/backtest-run`.

Room-1659 OPEN fades use the chat-reaction lane with durable opinion capture. - **Room 1659 counter-trade watches the shared HL portfolio wallet** `0xebf94fa19db7d2e7905decd01dae4ea9eb4c1ff2` (not the requesting user's personal Hyperliquid book) and opens the **opposite** perp leg on InverseAKITA via ACP/Virtuals Arena when room fills land. **`ALFACLUB_API_KEY`** posts chat cards only; HL execution uses Railway **`ARENA_*`** env. Room-wallet harvest/defense execute mode uses **`ALFACLUB_COUNTER_TRADE_USER_HL_AGENT_KEY`** on Railway (not the bot token).

- **`ARENA_ASSET_ALLOWLIST`** — optional comma-separated HL perp symbols (and `xyz:` HIP-3 pairs). When **unset**, counter-trade + inverse chat reactions + `runArenaTrade` allow **all** markets the executor wallet can trade. When set, it filters mirror entry, defense/harvest legs, and chat reactions at execution time (`pair_not_allowlisted` / `asset_not_allowlisted`). Set on **Railway Hermit** — Vercel env alone does not affect the counter-trade ticker.
